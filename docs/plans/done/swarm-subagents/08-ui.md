# 08 UI

**Goal:** the user can see what the swarm is doing and what it costs, and can stop it.

**Read first:** `app/web/frontend/src/components/ToolCard.tsx`, `UsageBadge.tsx`, `TurnStatus.tsx`, `MessageList.tsx`, `Composer.tsx`, `app/web/frontend/src/hooks/`, `app/web/backend/run_state.py` (events), `app/web/backend/routers/chats.py` (message and usage endpoints), `README.md` section 7 in this folder.

**Build:**
1. Backend events `worker_start`, `worker_step` (steps, euros so far) and `worker_end` (status), emitted from the worker runner through `run.emit` and included in the state snapshot a reconnecting client receives. An endpoint that serves a worker's side-file transcript, read only.
2. A delegate card: role, one-line task, worker model, live status, steps against cap, euros against `max_eur`, expandable transcript and output files. Concurrent workers give concurrent cards.
3. `UsageBadge`: tooltip split into planner and workers from `worker_cost_eur` (task 04).
4. `TurnStatus`: "N workers running".
5. Approval card for `delegate` that lists the contract.
6. Notices for `failed`, `over_budget` and stray-write findings.

**Acceptance:**
- Reloading the page mid-swarm shows the running workers and their costs.
- With no workers the chat looks as before.
- The euro figure in the card and the chat total agree to the cent after the turn ends.

**Tests:** backend event and endpoint tests in `app/web/backend/tests/`; for the frontend, `npm run build` and the type check. If the repo has no frontend tests, say so and put a manual checklist in the commit message.

**Out of scope:** a separate workers page, editing contracts in the UI.
